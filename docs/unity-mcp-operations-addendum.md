```markdown
## 原則6: トークン効率（コンテキストを汚さない操作）

MCP呼び出し1回ごとに結果全文がClaudeのコンテキストに積もる。無関係な中間結果は
トークンを消費するだけでなく精度も下げるため、節約と精度維持は同じ施策で達成する。

- **大量の同種操作は個別呼び出しを繰り返さない。** 同種操作がおおむね10件を
  超えるなら、C#エディタスクリプト1本（またはバッチ系tool）にまとめてUnity側で
  実行し、結果はサマリー（成功件数＋失敗分のみ詳細）で受け取る。
  バッチ実行手段の有無は原則0の手順5で実測する（無い実装ならこの項は適用外）。
  1件試行→目視確認→一括適用の規律（原則2）はバッチ実行でも維持する。
- **readは絞って取得する。** ヒエラルキー全体・Console全文を無条件に取得しない。
  対象パス・フィルタ・件数制限の引数があれば必ず使う。
- **同じ状態を二度readしない。** 直前のread以降に状態を変える操作をしていなければ
  再取得しない（失敗後の盲目的リトライ禁止と同根）。
- **Unity MCPはUnity作業をするプロジェクトだけに読み込む。** tool定義は
  毎セッションの固定費のため、グローバル設定に置かずプロジェクト側の
  `.mcp.json` に限定する（詳細: claude-unity-vpmリポジトリの
  docs/token-efficiency-guide.md）。
```
